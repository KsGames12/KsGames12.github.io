How to integrate AdMob in Unity without losing a weekend

Google's own docs get you 80% of the way there. The last 20% — mediation adapters, ad unit wiring, and testing without accidentally shipping test ads — is where most solo devs lose a Saturday.

STUDIO LOG · UNITY ADS

If you've shipped a mobile game before, you already know the shape of this problem. The Google Mobile Ads Unity plugin itself is simple to import. What eats your time is everything downstream of it: creating ad unit IDs in the AdMob console, matching them correctly to banner, interstitial, and rewarded placements in code, then repeating that whole process again for every mediation network you add — Unity Ads, AppLovin, Meta Audience Network, ironSource — each with its own adapter package and its own quirks.

The manual path

Here's roughly what setting this up by hand looks like:

  1. Create an AdMob account and register your app for iOS and Android separately.
  2. Generate ad unit IDs for each placement type you plan to show.
  3. Import the Google Mobile Ads Unity plugin and configure the GoogleMobileAdsSettings asset.
  4. Write loading, showing, and callback-handling code for each ad type — and usually duplicate a lot of that code across banner, interstitial, and rewarded.
  5. Add each mediation network's adapter SDK through the Ad Mediation Manager, resolve version mismatches, and rebuild.
  6. Test everything with test ad unit IDs, then remember to swap every single ID back to production before you build a release — this step alone causes more App Store rejections and lost revenue than almost anything else in mobile publishing.
The single most common mistake at this stage isn't a bug — it's a leftover test ad ID that ships to production, or a production ID that accidentally stays active during development and skews your test metrics.

Where the time actually goes

None of the individual steps above are hard. What makes AdMob integration slow is that it's repetitive, easy to get subtly wrong, and different for every project depending on which mediation networks you're using. A solo developer doing this from scratch is essentially hand-writing boilerplate that's nearly identical from one game to the next.

Mediation adapters specifically

Mediation is where things compound. Each network adapter has to be imported, matched to a compatible Google Mobile Ads SDK version, and configured with its own account IDs inside the AdMob mediation groups UI — separately from your Unity project. Miss a step and ads either fail to fill silently or, worse, appear to work in testing and then fail once real traffic hits a mediation waterfall.

Automating the repetitive part

This is exactly the gap the Ad Integration Toolkit (formerly Quick AdMob Integrator) is built to close. It's a Unity editor extension that:

  • Configures your ad unit IDs directly from the editor instead of hand-editing scripts.
  • Generates the ad manager scripts for banner, interstitial, and rewarded placements, so you're not rewriting the same callback boilerplate per project.
  • Automates mediation adapter setup, cutting down the manual matching between adapter versions and the Google Mobile Ads SDK.
  • Supports testing ads directly in-editor, so you can verify placements before you're deep into a build-and-check loop on a device.

The goal isn't to hide what AdMob is doing — it's to remove the part of the process that's purely mechanical, so the time you do spend on ads goes toward placement and pacing decisions that actually affect revenue, not toward re-reading SDK version tables.

Who this is for

If you're a solo Unity developer or a small team shipping more than one mobile title, the setup cost of AdMob and mediation repeats every time you start a new project. Tooling that automates the repetitive 80% is most valuable exactly there — on your second, third, and tenth game, not just your first.
